# Сквозной сценарий компании: проверка 25 октября 2026

AI/Data выполняет путь от разрешённого источника до персонального кандидата. Настоящие Symfony и пользовательский интерфейс через него ещё не подключены. Пошаговая инструкция — [как работает процесс](ai-process.md), схема интеграции — [контракт](../contracts/intelligence/README.md).

## Что доработано

| Звено | Результат |
|---|---|
| Профиль | Все направления сохраняются; неизвестное не становится услугами. Продукты, ресурсы, затраты, рынки, контрагенты и ограничения хранятся как утверждения с происхождением, статусом и датами. |
| Настройки аналитика | Baseline доступен сразу. `optimize` отдельно вызывает разрешённый `generator` с общим бюджетом; сбой сохраняет рабочую версию. |
| Применение | Настройка влияет на порядок и расширения поиска, исследователя, аналитика, критику, глубину и горизонт. `--analyst` также применяется к DataTask. |
| Отбор | Используются направления, ресурсы и зависимости, включая фразы из процитированных сообщений. Приоритет не является вероятностью ущерба; есть ограниченный просмотр нулевых сигналов. |
| Проверка | В гипотезе нельзя использовать деятельность или факт об отсутствии данных как подтверждённую зависимость. Repair получает конкретные безопасные коды ошибки. |
| Пересмотр | Версии профиля и digest политики защищены от старых задач; откат меняет стратегию, сохраняя текущий профиль. |
| История | `as_known` не использует будущие публикации или профиль без подтверждённого времени знания. Исторический EventStore изолирован; старый документ не становится новой текущей версией. |
| Публикация | Python возвращает кандидата. Core проверяет все компании batch, версии и scope до outbox и дедуплицирует подпись. |

## Воспроизвести

Из корня репозитория:

```sh
docker compose run --build --rm intelligence demo-business
docker compose run --build --rm intelligence-test
```

Первый вызов читает два локальных RSS и анализирует две синтетические компании. Два сообщения об одном терминале дают одну группу с противоречащими цитатами; отдельная аналогия не доказывает влияние. Получаются два события и четыре baseline-кандидата. Модель и сеть источников по умолчанию не вызываются. [Вход](../apps/intelligence/examples/business-scenario.json), [ожидаемые основания и недопустимые выводы](../apps/intelligence/evaluation/business-scenario.json).

## Настоящие модели и пределы проверки

Живые прогоны используют Qwen3.6, Gemma 4 и GLM-5.3-Flash через прежний OpenRouter scope и только синтетические профили/RSS. Генерация, выбранная конфигурация, анализ/repair/критика и откат проверяются отдельно от pytest. Сохранённые расходы и результаты — в [машиночитаемом отчёте](checks/business-workflow-2026-10-25.json). Неудачные прогоны включаются в расход; это не выборка для статистического сравнения.

Турнир механически работает, но улучшение смыслового качества не доказано: нужны независимые задания, экспертная разметка и свежие holdout/shadow. Аналитический пример не устанавливает истинность сообщений о терминале. Произвольные новости с разными заголовками и одним бизнес-механизмом не объединяются автоматически с гарантированной смысловой точностью; окончательное сопоставление и публикация принадлежат Core.

Поиск ограничен разрешённым корпусом и настройками источников, полнота отбора не измерена. Потребуются настоящая интеграция Symfony/UI, разрешённые банковские CSV/PDF и тарифы Альфы. При чтении metadata 25 октября gateway отвечает `200`, показывает шесть моделей, максимальный бюджет 500 и spend 0; ни у одной модели нет обеих ставок. Генеративных вызовов через Альфу не было.


На описанный здесь предыдущий этап списано **$0.013024234000**, накопительно **$0.039433723306 из $5**, осталось **$4.960566276694**. Неопределённых резервов нет. Первый ряд прогонов выявил ошибку старых context ID в промпте, излишнее ограничение primary evidence одним представителем события и нестабильный формат ответов. Ошибки промпта/проверок исправлены; невалидный ответ теперь даёт явный baseline с цитатами и partial, сохраняя расход. Последний GLM-прогон вернул модельный partial с двумя противоречащими сообщениями и неизвестным влиянием; применённый ref совпал с выбранным, откат завершился. Это подтверждает исполнение сценария, не статистический выигрыш качества.

Фактическое применение настройки: `workflow.py` передаёт сохранённый config в `MultiAgentPipeline`; `multi_agent.py` использует его в плане поиска, researcher/critic и повторном анализе; `pipeline.py` — в порядке поиска, лимите evidence, примерах, горизонте и проверке глубины. Предпочтения пользователя применяются отдельно к копии конфигурации; baseline и профиль не перезаписываются.

Реестр с более ранними конфигурациями поддерживается без перезаписи: новые default-поля нормализуются при сравнении, исходные JSON и hash неизменяемой версии сохраняются.
