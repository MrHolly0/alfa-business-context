# Проверка общего запуска

26 октября 2026 года ветка `feature/core` объединена с актуальным `main`, включая PostgreSQL-хранилища AI/Data. Проверен работающий локальный путь: браузер → nginx → Symfony Core → Python API → PostgreSQL.

## Что доступно

- Вход и выход с серверной cookie-сессией; список только доступных пользователю компаний.
- Чтение и изменение контекста компании с проверкой версии.
- Создание показателя, сохранение значения с периодом, единицей и источником; чтение после перезагрузки страницы.
- Новости, документы и сохранённые оценки из Core. Сам интерфейс пока не регистрирует источники и не запускает сбор: это команды оператора.
- Прямой HTTP-вызов AI/Data из `run-news.php`. Python в PHP-контейнер не установлен; провайдерские ключи туда не передаются.

Старый макет на данных браузера открывается отдельно кнопкой «Посмотреть демо». Рабочий режим не подставляет его метрики или результаты вместо ответов Core.

## Docker

```sh
docker compose up --build --wait
```

Откройте http://localhost:4173. Учебная запись: `demo@alpha.test` / `DemoAlpha2026!`. При сохранённых настройках старой версии может потребоваться повторный вход. Пользовательский `.env` менять или заменять не нужно.

Порядок запуска: PostgreSQL → отдельные роли/БД Core → схемы и миграции → Core/API → web. Внутренний bearer, секрет PHP и его сессии сохраняются в отдельных volumes. Рабочие процессы имеют непривилегированные UID; файловые системы контейнеров read-only, запись разрешена в выделенные volumes и временные каталоги. Порты опубликованы только на loopback. PostgreSQL и AI raw volume из предыдущей версии сохранены.

Core и AI используют разные БД и роли. На настоящем сервере проверено, что Core app не может подключиться к AI БД, а AI app — к Core БД. Рабочая роль не получает миграционные credentials. `/health` проверяет доступность своего хранилища. Web повторно разрешает Docker DNS, чтобы адрес Core не оставался устаревшим после пересоздания контейнера.

Повторная команда запуска не очищает таблицы и не заменяет внутренние секреты. Пароли-примеры предназначены для локальной разработки; отключение учебного seed само по себе не удаляет уже созданную учётную запись. Подробные параметры и команды остановки — в [инструкции Docker](../infra/README.md).

## Публичные новости через настоящий HTTP

На отдельном стенде зарегистрирована RSS-лента пресс-релизов Банка России `https://www.cbr.ru/rss/RssPress`. PHP отправил разрешённый снимок в Python API; ответ HTTP 200 содержал `partial`. В Core сохранены **14 документов/ревизий**, **14 событий** и **10 baseline-оценок** в пределах ограничения числа анализируемых событий. Повторный сбор добавил **0 документов** и не создал дубликатов. После изменения контекста новый запрос также завершился HTTP 200.

Это проверка реального источника и связи сервисов. Внешняя модель не вызывалась. `partial` не означает готовую причинную интерпретацию: baseline возвращает ограничения, на этом историческом срезе сводка компании имела статус `no_analysis`. В текущем Core она читается из последнего сохранённого запуска и отмечает устаревшие версии.

При интеграции исправлены ошибки: разрешённые article hosts теперь читаются из сохранённого JSON; начальный пустой профиль получает реальную версию до первого AI-вызова; контекст/source writers и публикация результата проверяют версии под одной короткой блокировкой компании. HTTP-запрос не выполняется под этой блокировкой.

## Чистый judging-запуск и модельный HTTP сценарий — 26 октября

На отдельном проекте Compose с новыми данными прошли первая подготовка и повторная подготовка judging-кейса, включая проверку разрешённых файлов, импорт, OCR и baseline HTTP-анализ. В основной функциональной проверке `U_57706`, `U_9250` и `U_408263` прошли Web → Core → Python → шлюз Альфы → сохранение Core: каждый запрос вернул HTTP 200 после трёх модельных обращений; критик принял семантическую проверку, `errors[]` был пуст. Параллельный запрос для занятой компании получил HTTP 409 за 0,13 секунды.

Все три ответа получили `partial`: ограничения исходных данных и покрытия остаются видимыми. Это подтверждает сквозную работу ограниченного сценария, но не доказывает точность, полноту или экспертное качество выводов. Единицы выручки и платежей не подтверждены, а независимая экспертная разметка не проводилась. Подробности подготовки и состава данных — в [инструкции для судей](judging.md).

После перезапуска отдельного стенда сохранились 38 документов, 704 записи доказательств и один результат workflow; повторный вход и чтение сохранённого запуска прошли. Браузером проверены вход, выбор компании, восстановление модельной оценки, цитаты и список источников. Исправлены сбой обзора, ссылка без ID события и выдача устаревшей сборки из кэша. Конфигурация нового web-образа прошла `nginx -t`, контейнер — healthcheck. Python: 518 тестов и 18 subtests; Web: 46 тестов, сборка и проверка артефакта; Core: интеграционные проверки пройдены.

В ledger Альфы сохранены 13 резервирований в состоянии `uncertain`, суммарно 130 ₽, доступный локальный остаток — 370 ₽. Фактическую стоимость шлюз не сообщил; эти значения не являются подтверждённым списанием.

## Что ещё не подключено

Полная очередь Core с claim/lease/heartbeat/result/failure, автоматический PHP hook персонализации, браузерное управление источниками и банковская SSO не проверены этим запуском. Обычный локальный режим остаётся baseline; модельный путь включается отдельным judging overlay. Сквозная модельная проверка через шлюз Альфы описана выше и не подтверждает промышленную готовность. На срезе прежней проверки основной lifetime spend остался **$0.060988221306**, открытый резерв — **$0**; это историческое значение, не текущий счёт.

Опциональный scheduler вызывает существующий Core CLI раз в минуту, обрабатывая каждую компанию не чаще раза в час. Это один локальный процесс расписания, без гарантий распределённой очереди или нескольких его реплик. Схема Core пока устанавливается идемпотентным `schema.sql`; она не подменяет версионированные миграции AI/Data или будущую систему миграций Core.
