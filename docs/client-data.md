# Подготовка контекста компании из CSV

Модуль `intelligence.client_data` превращает ограниченный CSV с обезличенными полями кейса в **предложение** профиля компании. Он не сохраняет профиль в Core, не угадывает юридические названия и не вызывает модель. Сохранение контекста и проверка прав остаются за Core.

## Вызов

Вход можно передать как текст CSV или как уже разобранные строки:

```python
from intelligence.client_data import parse_company_csv

prepared = parse_company_csv(
    csv_text,
    tenant_id=authenticated_tenant_id,
    filename="case.csv",
    origin="operator-upload",
    revenue_unit=None,  # неизвестная единица остаётся неизвестной
    roles_by_synthetic_u={},
    affected_company_ids=None,
)
for proposal in prepared.proposals:
    # Core сам проверяет tenant и решает, сохранять ли proposal.context.
    print(proposal.company_id, proposal.context.industry, proposal.revenue.qualification)
```

`CompanyContextPrepareRequest` — закрытая Pydantic-модель для границы API. Core должен установить `tenant_id` по аутентифицированному principal; значение из запроса пользователя само по себе не является разрешением. `prepare_company_contexts(rows, **kwargs)` — тот же нормализатор для строк, уже разобранных API. Результат `CompanyContextPrepareResult` содержит число входных/выбранных/отфильтрованных строк, неизвестные ID и список предложений.

`CompanyContext` сохраняет прежние `industry`, `description`, `role`, `dependencies` и `facts` и добавляет `schema_version=company-context-v2`, список `activities` и список `assertions`. `CompanyActivity` хранит исходную метку, необязательный закрытый `normalized_class`, статус, provenance и период действия. Неизвестная деятельность остаётся без нормализованного класса. `CompanyAssertion` — общий тип для продукта, ресурса, затрат, рынка, территории, поставщика, клиентской группы, договора, горизонта и зависимости; у него есть статус (`confirmed`, `assumption`, `contradiction`, `unknown`), происхождение и даты. Отсутствующие сведения не превращаются в отрицательные утверждения.

Для анализа и поиска общий helper `intelligence.company_context.project_company_context(context, as_of=...)` возвращает только подтверждённые сведения в периоде действия, а нерешённые сведения, ограничения и конкретные вопросы — отдельно. Старые facts/dependencies без даты сохранены для обратной совместимости; проекция помечает их `freshness_unknown` и просит подтвердить актуальность. `fingerprint` — SHA-256 слепка проекции, полезный для сравнения версии контекста, но не заменяющий Core version/CAS.

Фильтр `affected_company_ids` сравнивает точные значения `SYNTHETIC_U`. Не совпавшие ID возвращаются в `unknown_affected_company_ids`; нулевое совпадение даёт пустой `proposals`, а не подменяет фильтр. Повторный `SYNTHETIC_U` считается неоднозначным и отклоняет весь ввод.

## Что переносится и как

- `SYNTHETIC_U` становится `company_id` и анонимизированной меткой. По нему нельзя восстановить или предположить имя организации.
- `MAINOKVED_NAME` и все непустые поля `ACTIVITY_*`/`OKVED_*` с описанием деятельности становятся отдельными `activities` с `filename#row=N,column=...` provenance. Первое направление не обрезает остальные. Для части знакомых формулировок присваивается грубый нормализованный класс; для незнакомой формулировки он равен `null`, и деятельность не классифицируется как услуги. Страна, регион и исходная выручка остаются фактами. Роль попадает в `CompanyContext.role` только из переданной Core-картой `roles_by_synthetic_u` или явного столбца `ROLE`/`USER_ROLE`/`COMPANY_ROLE`.
- Единица `REVENUE_COMPANY` не выводится из величины. Её нужно явно передать как `RUB` или `thousand_RUB` (либо указать в допустимом `REVENUE_UNIT` самой строки). Конфликт строки с единицей, заданной оператором, оставляет квалификацию неизвестной. Граница крупной компании строго больше 15 млрд RUB; ровно 15 млрд — «на пороге/ниже». Ошибка формата числа отражается предупреждением.
- Продуктовые флаги возвращаются как `true`, `false` или `null`. Отсутствующий столбец, пустое или непонятное значение остаётся `null`, а не отрицанием продукта.
- `GROUP_ID` сохраняется только как наблюдаемая принадлежность к группе. Он не становится связью поставки, владения или контроля.
- Платёжные поля создают отдельное `PaymentObservation`. Если указаны обе стороны, дополнительная связь имеет `kind=payment_observation`, `status=hypothesis`. Ни сторона платежа, ни направление перевода не трактуются как поставщик, покупатель или подтверждённый контракт.

## Ограничения формата

Парсер принимает UTF-8-текст размером до 10 MB, до 500 непустых строк, до 256 столбцов и до 8 000 символов на поле. Имя файла — только листовое имя `.csv`. Разрешены только известные поля кейса и столбцы с префиксом `PRODUCT_`; произвольные столбцы отклоняются, чтобы не протащить персональные или неописанные данные. Повторяющиеся нормализованные заголовки, лишние ячейки и пустой/отсутствующий `SYNTHETIC_U` также отклоняются.

Переданный `origin` и имя файла — метки происхождения, а не проверенное доказательство права на данные. Модуль не загружает файл и не пишет его на диск; загрузку, авторизацию и хранение выполняет вызывающий Core-контур. Никакой приватный CSV не отправляется во внешнюю модель.

## Фактический набор организаторов

Закрытый набор организаторов хранится вне Git в `.local/data/case/`. Большие исходные CSV импортируются Core отдельным потоком; `client_data` готовит предложение только для явно выбранных `SYNTHETIC_U`. Подготовительный private importer сохраняет реальные номера строк, происхождение полей и неизменённую исходную выручку.

- `df_Uid_data_hack.csv`: 85 525 строк компаний; Core импортировал 85 513 однозначных профилей. 12 конфликтующих строк для `U_428697` исключены из профилей, исходный файл сохранён без изменений.
- `df_Fid_Uid_link_hack.csv`: 12 514 строк связей. `df_Uid_payment_hack.csv`: 1 380 585 агрегатов платежей. Core сохраняет исходные идентификаторы и значения, включая ссылки на отсутствующие профили; они не становятся подтверждёнными связями поставки или выручкой.
- Для демонстрации подготовлены три предложения профиля из 24 полей исходного CSV. Единица `REVENUE_COMPANY`, валюта и период платежей неизвестны; профили не подтверждают прохождение порога 15 млрд рублей.
- Нормализатор полного CSV выше принимает небольшой API-ввод до 500 строк. Он не является bulk importer для исходного набора; локальная подготовка выбранных компаний и OCR описаны в [документации корпуса](../apps/intelligence/docs/corpus.md), а воспроизводимый judging setup — в [инструкции проверки кейса](judging.md).
