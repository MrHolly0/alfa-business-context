# Проверка перехода AI/Data на PostgreSQL

Проверка выполнена 25 октября 2026 года на настоящем PostgreSQL 17.11. В команде не была зафиксирована версия, поэтому выбран поддерживаемый PostgreSQL 17; образ закреплён как `postgres:17.11-bookworm`. Доступ — Psycopg 3 с ограниченным пулом, без ORM. Рабочая база `business_context_ai`, отдельная проверочная — `business_context_ai_test`.

## Что перенесено

Корпус документов, ревизии, фрагменты-доказательства, происхождение, опрос источников и receipts; события, общий пакет и исторические снимки; глобальные и персональные конфигурации, история активаций, турниры и оценки; бюджет, идемпотентность, аналитические результаты, outbox и состояние выполнения.

Канонический профиль компании остаётся в Symfony. Python получает версионированный snapshot и сохраняет принадлежащие анализу артефакты. HTTP/JSON-контракты не изменены; экспорт схем проверен. Прямой записи в таблицы Core нет. Бизнес-очередь, права, расписание и публикация остаются обязанностью Core. PostgreSQL leases координируют исполнителей AI/Data и не создают вторую бизнес-очередь.

В таблицах сохранены IDs, версии и ссылки. Первичные/уникальные ключи и внешние ключи включают `store_key`; включён принудительный RLS. Деньги — `NUMERIC`/`Decimal`, даты — `TIMESTAMPTZ` с выдачей UTC. Логические флаги сохранены как 0/1 с CHECK; необязательные значения остаются NULL. JSON-текст сохраняет исходную сериализацию и хеши.

## Выполненные проверки

| Сценарий | Результат |
|---|---|
| Чистая установка и повтор миграций | Все 12 миграций на новой БД; повтор — `applied: []`. Проверен и последовательный upgrade тестовой БД; no-op миграции не берут DDL locks на рабочие таблицы |
| Чтение/запись контекстных артефактов, конфигураций, доказательств и результатов | Полный набор тестов использует PostgreSQL; миграции находятся также в собранном wheel |
| Сквозной анализ | Локальный синтетический RSS → корпус → два события → четыре кандидата; без внешней сети и моделей |
| Турнир → публикация → применение → откат | Проверен сохранённый lifecycle и CAS ревизий. Модель/судья заменены тестовыми ответами; это не новая проверка качества моделей |
| Независимые процессы | Конкурентное сохранение одного документа, события и кандидата; CAS публикации и отката; борьба за execution slot |
| Повторная доставка | Идемпотентность кандидата/outbox и контрактный worker; повтор HTTP после рестарта вернул идентичный ответ |
| Бюджет | Восемь процессов при cap=3 получили ровно три резерва; конкурентный резерв ждёт settlement того же счёта и учитывает фактический расход |
| Устаревший результат | Проверены context/version fences и запрет записи более старого анализа поверх нового |
| Сбой транзакции | Инъекция ошибки откатывает вставки; DB-only retry конечен и не сохраняет строки неудачных попыток |
| Восстановление выполнения | Uncertain-запуск блокирует автоматический повтор до явного recovery; активный lease нельзя восстановить |
| Ожидание HTTP | Во время блокирующего тестового fetcher нет AI-сессии `idle in transaction` |
| Перезапуск контейнеров | После рестарта PostgreSQL живой процесс восстановил пул и прочитал тот же результат без нового сбора; после рестарта API повторный HTTP-ответ совпал |

Полный набор проверен на Python 3.14 хоста и Python 3.12 контейнера. Окончательные результаты — **473 теста и 11 subtests**, без пропусков. Есть предупреждения зависимостей FastAPI/httpx и старого теста с `fork`; новые процессные проверки используют `spawn`. GitHub Actions обновлён, но удалённый CI в этот отчёт не включён.

## Существовавшие данные

Все **62 SQLite-файла** из прежнего private volume сначала прошли dry-run и реальный импорт в тестовую базу. Затем перенесены в новую отдельную основную БД. Для каждого проверены integrity/FK, количество строк, IDs/связи и повторный импорт. Исходный volume монтировался только для чтения; хеши DB/WAL/SHM до и после совпали. Очередь Core Stand среди этих файлов отсутствовала.

| Компонент | Файлов | Исходных строк |
|---|---:|---:|
| Общие конфигурации | 6 | 27 |
| Опрос источников | 10 | 141 |
| Персональные конфигурации | 14 | 28 |
| Корпус и доказательства | 11 | 201 |
| События и снимки | 9 | 129 |
| Workflow | 9 | 209 |
| API/outbox | 1 | 0 |
| Бюджет | 1 | 176 |
| Турниры | 1 | 116 |

Основной бюджетный scope `alfa-openrouter-paid-tests` сохранил точный lifetime spend **$0.060988221306**, лимит **$5** и нулевой открытый резерв. Экспериментальный scope сохранил собственный учёт **$0.009869480**; это дополнительная внутренняя квота, её нельзя прибавлять к основному счётчику как отдельный платёж провайдеру. В ходе миграции LLM не вызывались.

Хостовый `apps/intelligence/.state/corpus.sqlite3` отдельно проверен: три таблицы пусты, данные для переноса отсутствуют. Он сохранён. Ни один прежний SQLite-файл не удалён. Raw-файлы не переносились в SQL: они остаются в прежнем volume, их refs и хеши сохранены. Legacy reservations без lease-полей импортируются как uncertain с истёкшим lease, без автоматического повторения модели; преобразования записаны в manifest.

## Команды для команды

Из корня репозитория:

```sh
# Отдельный PostgreSQL и миграции основной AI/Data БД
docker compose --profile database up -d --wait postgres
docker compose --profile database run --build --rm intelligence-migrate
docker compose --profile tools run --build --rm intelligence db check

# API и отдельная тестовая БД с автоматическими миграциями
docker compose --profile analysis up --build --wait intelligence-api
docker compose --profile test run --build --rm intelligence-test

# Контролируемый импорт одного остановленного legacy-хранилища
docker compose --profile tools run --rm intelligence-import import-sqlite \
  --source /legacy/corpus.sqlite3 --component corpus \
  --logical-path /app/.state/corpus.sqlite3 --confirm-quiesced --dry-run
```

Для фактического импорта повторите последнюю команду без `--dry-run`. Уже выполненный импорт не объединяет данные повторно: при неизменном источнике и целевых counts вернётся `already_imported`; изменившийся источник/непустая или изменившаяся цель дают явный отказ. Dry-run проверяет совместимость схемы, но не заменяет проверку ограничений при реальной вставке.

Хостовые DSN, восстановление прерванного выполнения и разделение ролей — в [инструкции PostgreSQL](postgresql.md). Подключения разработчика Symfony и примеры бизнес-запросов остаются в [инструкции интеграции](symfony-integration.md).

## Границы проверки

Настоящие Symfony Core, его очередь и шлюз Альфы в этом прогоне не подключались. Контракт проверялся стендом; LLM/HTTP для аналитических тестов заменены разрешёнными фикстурами. Переход на PostgreSQL не доказывает качество аналитики и доступность конкретного провайдера.

Для развёртывания нужны собственные пароли/DSN AI/Data, миграционный запуск до API/worker и доступ всех исполнителей к общему файловому хранилищу оригиналов. Локальные пароли Compose предназначены для разработки. Тестовая БД отделена от основной, а тестовый запуск отказывает при имени БД без суффикса `_test`. Роль Core и его таблицы передавать Python не требуется.

SQLite остаётся только в read-only импортёре, legacy-файлах и fixture-only Core Stand. Второго production backend хранения нет.
