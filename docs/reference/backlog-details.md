# Backlog хакатонного прототипа и развития

## Правила планирования

- MVP закрывает явные требования брифа и демонстрируемый сквозной сценарий. Команда — четыре активных участника: Product/BA + Prompt Engineer совмещает пользователь; отдельно Frontend, Backend и один ML Engineer. Продуктовый PDF v3 описывает пять раздельных ролей, включая двух ML-специалистов (с. 38), поэтому текущая команда покрывает их совмещением функций. Пятый участник сейчас в отъезде, не закладывать на него блокирующие задачи и срок неизвестен.
- P0 в этом backlog — приоритет кейсового MVP/сдачи; P1 — расширение после MVP; P2 — интеграция/пилот. В PDF v3 собственный P0 значит «до пилота» и не переносится автоматически в хакатонный MVP.
- Текущий runtime — Node-прототип в `apps/web/{web,worker,scripts,tests,data}`; он не является целевой платформой и не меняется без отдельной миграции. Целевое предложение v3 для кейсового MVP: Symfony/PHP Core + Python/FastAPI `apps/intelligence` + PostgreSQL jobs + лексический поиск; минимальный Core job/outbox/claim/result и DB isolation — приоритетный технический срез, полный production runtime — пилот. Java/Spring больше не планируется. `contracts` и текущий `infra` поддерживают разработку/локальный запуск. Kafka/Redis/Qdrant/AlfaGen/Mercure не считаются доступными без подтверждения. См. [ADR-001](../decisions/001-symfony-core.md).
- Доступ к данным, моделям, банковским API и инфраструктуре считается зависимостью, а не предпосылкой, пока он не подтверждён. Mock/synthetic допускается для демо с маркировкой.

## Реализованный срез

В R-04/R-05 реализован Python-слой провайдеров: OpenRouter для разработки и хакатонный шлюз, точные model IDs из инструкции по ключам, один явный запрос без автоматических повторов, usage/стоимость и атомарные локальные резервы SQLite. Сравнение тарифов — расчёт для той же модели по заданным ставкам. Это частичное выполнение: нет интеграции с Core job, общего межсерверного бюджета, live-проверки ключей или полного аналитического pipeline. Подробности и команды — [провайдеры и бюджет](../llm-providers.md).

## Риски, блокирующие обещания

- Нет подтверждения, что перечисленные CSV и аналитические PDF фактически доступны в рабочем каталоге; сначала R-02/R-03.
- Единицы `REVENUE_COMPANY` не указаны в брифе, а имя файла платежей неоднозначно (бриф, с. 15–16). Отбор крупного бизнеса и модель связей без проверки могут быть неверны.
- Не подтверждены ключ, точные API model_id, цены/usage и централизованный контроль лимита; дневные 500 ₽ нужно считать общими для команды.
- Продуктовый PDF v3 предлагает Symfony/PHP, но не подтверждает его допуск в банковскую среду. SSO, оболочка/gateway, AlfaGen, Kafka, Redis, Qdrant, PostgreSQL/S3 и SSE hub остаются открытыми вопросами.
- Для приватного репозитория требование дать доступ `alfa-hack-2026`; это release-действие, его выполнение должно быть явно включено в чек-лист дедлайна.
- Исторический README прототипа был ориентирован на малый бизнес, а notices не перечислял npm-зависимости; root-документация уже исправлена. Остаётся проверить operator mapping legacy aliases моделей и допустимые API model_id.
