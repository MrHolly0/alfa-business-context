# Ближайшие задачи

Наша следующая цель — один рабочий сценарий: выбрать компанию, добавить новость и получить объяснение её влияния с источниками. Сначала собираем этот путь целиком, затем расширяем.

## Что уже есть

- `apps/web` — работающее веб-интерфейс на React.
- `apps/intelligence` — Python-адаптеры моделей и учёт расходов. Полного анализа новостей пока нет.
- `apps/core` — описание будущего PHP-ядра. Приложение Symfony ещё нужно создать.

## Что берём сейчас

| Кто | Первая задача | Что передать команде | Когда готово |
|---|---|---|---|
| БА + промпты | Выбрать один сценарий и подготовить два профиля компаний, одну новость и ожидаемый разбор | Примеры входа и результата; поля, которые обязательно нужны пользователю | По примеру понятно, почему новость важна одной компании и менее важна другой; факты, позиция банка и предположения различимы |
| Backend | Создать Symfony-приложение в `apps/core`; реализовать сохранение компании и задания на анализ | Команды запуска, HTTP-запросы и тестовый ответ для фронтенда и Python | Данные сохраняются; запрос анализа возвращает идентификатор задания, по которому можно прочитать состояние |
| ML | На базе `apps/intelligence` собрать первый разбор новости: взять профиль и текст, вызвать модель, проверить структуру результата | Python-команду для того же примера и JSON результата | Ответ содержит основания и неизвестные данные; модель не выдумывает позицию банка; расход вызова записан |
| Frontend | Подготовить выбор компании, ввод новости и показ результата в `apps/web/src` | Работающий экран на согласованном JSON; затем подключение к API Core | Есть состояния ожидания, результата и ошибки; пользователь может открыть источник и отличить факт от предположения |

Для примеров можно использовать синтетические данные с явной отметкой. Реальные ключи и клиентские материалы в Git не кладём.

## Как соединяем части

1. БА, Backend и ML согласуют один вход и один результат в `contracts/examples/`. Существующие JSON — отправная точка, их нужно проверить на выбранном сценарии.
2. Frontend работает на этом примере, Backend сохраняет задание, ML запускает анализ отдельной командой. Эти задачи можно делать параллельно.
3. Backend и ML соединяют получение задания и отправку результата по [контракту](../contracts/README.md). PHP хранит итог и отдаёт его интерфейсу.
4. Все вместе прогоняем пример от начала до конца, затем проверяем новую новость, которую не использовали при настройке.
5. По результатам считаем качество и стоимость. После этого берём дополнительные источники и фоновое обновление.

## Что пока откладываем

Банковский SSO, Kafka, векторную базу, сложный граф связей, высокую доступность и промышленную эксплуатацию. Они не должны блокировать первый рабочий сценарий.
