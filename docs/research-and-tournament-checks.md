# Косвенное влияние, поиск и турнир — 25 октября 2026

В этой проверке использованы новые синтетические компании и документы, настоящий Python workflow и GLM через OpenRouter. Подключение Symfony и генерация через шлюз Альфы этим не подтверждаются. [Примеры подключения для Symfony](symfony-integration.md).

## Что изменилось в исследовании

Раньше неподтверждённая зависимость могла попасть в вопрос, но обычный workflow не включал её в поисковые запросы. Теперь текущие предположения и неизвестные зависимости становятся ограниченными поисковыми подсказками. Они получают отдельный исследовательский сигнал, без подтверждённого пути воздействия. Противоречащие, просроченные и ещё не известные на дату анализа сведения не используются как действующие подсказки. Неизвестная свежесть явно сохраняется.

Подсказки ограничены шестью короткими записями. В них не дублируются длинные provenance и списки ссылок. Их ID нельзя использовать вместо подтверждённого контекста для гипотезы воздействия или рекомендации. Если применимость не установлена, модель возвращает `unknown` и конкретный вопрос. Проверка границ не позволяет автоматически превратить предположение в факт профиля.

Внешний поиск по корпусу теперь учитывает и сведения компании: это помогает получить документ о промежуточном поставщике, который не назван в исходной новости. При нулевом лексическом сигнале scheduled workflow сохраняет ограниченный исследовательский просмотр (`max_exploratory_analyses`, по умолчанию один). Это снижает риск пропуска, но не гарантирует полноту отбора.

| Неизвестный TransitLeaf | В профиле есть только предположение об использовании платформы. Оно добавляет поисковый запрос и исследовательский сигнал `0.2`, но не подтверждённый dependency path. Модель не заявляет использование сервиса: спрашивает, используется ли он, какая версия и выполнено ли обновление. |

У первых трёх случаев начальный лексический приоритет равен нулю: прямой связи исходного события с профилем отбор не нашёл. Модельный этап запущен ограниченным исследовательским просмотром; реальные запросы и полученные документы записаны в отчёте. Ни названия компаний, ни ответы не зашиты в runtime-условия.

В обоих прогонах по четырём случаям выполнено по восемь реальных обращений к модели: анализ и критика. Все кандидаты остались `partial`. Это проверка оснований и исполнения на четырёх случаях, не независимая экспертная разметка. Модель всё ещё может слишком категорично пересказать прогноз источника; цитаты, авторство прогноза и условия применимости нужно показывать рядом с выводом. В первом отрицательном примере неоднозначность дат позволила модели ошибочно назвать дату уточнения; даты документов сделали явными, отдельный повтор использовал корректные даты старого бюллетеня и опровержения.

## Что доступно поиску

- Collector получает только источники из разрешённого Core snapshot: RSS/Atom, согласованный HTML/PDF и JSON с заданным mapping. Возможность парсера не означает подключённую подписку.
- В текущей разовой сетевой проверке RSS Банка России получены **14 публикаций**, без ошибок; сохранены текст и оригинал с SHA256. [Результат получения](checks/source-collection-2026-10-25.json). Это внешний источник, **не позиция аналитиков Альфа-Банка**. Постоянная подписка и расписание не создавались.
- Исследователь предлагает запросы и недостающие сведения; код исполняет поиск в уже разрешённом корпусе. Критик может предложить до двух дополнительных запросов и один повтор анализа в оставшемся бюджете. Это не запрос произвольного сайта и не автоматическое расширение прав.
- Для нового источника Core должен проверить право, выдать grant/policy и поставить `collect`. Для закрытого факта компании — получить ответ пользователя и новую версию профиля. Банковские CSV и девять аналитических PDF по-прежнему не предоставлены.

`usage.search_coverage` и trace показывают разрешённые source IDs, размер снимка документов, выбранные evidence, подсказки и пустые каналы поиска. `coverage.limitations` и уточнение объясняют, что поиск ограничен корпусом. Ненайденное воздействие не означает отсутствия риска. При исключении источника или изменении временной границы нужное звено может стать недоступным — тогда цепь не считается установленной.

`demo-research --input` позволяет менять локальные примеры в baseline. Модельный режим демо разрешён только для встроенного синтетического набора; произвольный файл нужно передавать обычным заданием с доверенной классификацией и политикой Core.

## Турнир с настоящей моделью

Реальная GLM сгенерировала две допустимые конфигурации. Они зарегистрированы неизменяемо и сравнивались с baseline на одинаковых входах, инструментах и лимитах. Отдельный проверочный случай — другой бизнес и другое событие; генератор не получает его содержание. [Полный отчёт, настройки и все попытки](checks/tournament-live-2026-10-25.json), [точный набор заключительного прогона](../apps/intelligence/evaluation/tournament-integration.json).

| Попытка | Фактический результат |
|---|---|
| Первая | Получены два кандидата. Один модельный ответ отклонён обязательными проверками. Запрос судьи оказался больше входного лимита: 29 567 против 24 000 единиц консервативной оценки. Baseline сохранён. |
| Повтор генерации | Модель не вернула допустимых настроек. Стоимость учтена; неподходящие настройки не зарегистрированы. |
| Проверка исправленного судьи | Ранее принятые конфигурации повторно оценены, модельный судья действительно вызван. Один кандидат выиграл train, но второй порядок holdout остановлен консервативным пределом серии. Это не доказанное ухудшение кандидата. |
| Заключительный прогон | Оба сравнения завершены в обоих порядках. У первого кандидата разошлись оценки при перестановке — ничья; второй уступил baseline. Сохранён baseline, его отдельный holdout прошёл. Следующий `DataWorkflow.analyze` использовал именно активный baseline и правильный private config ref. |

Для судьи устранено троекратное дублирование evidence: полные цитаты, ссылки, происхождение и даты передаются один раз. Ответы сохраняют claims, influence chain и вопросы со ссылками. Тот же вид используется в слепом пакете эксперта. На записанной паре размер входа уменьшился до 21 665. Ошибки сравнения теперь содержат безопасный код и порядок, в котором произошёл сбой.

В заключительной проверке лимит серии учитывал фактические списания после settlement и незакрытые резервы, а не сумму уже освобождённых максимумов. Общий счёт и пул экспериментов не менялись. Всего в турнирных попытках — 24 реальных вызова, из них девять обращений к судье. Непрохождение формата, ничья и сбой никогда не становятся победой.

Синтетический набор не публикуется как рабочий победитель. Экспертного одобрения, независимой реальной shadow-выборки и доказанного прироста качества нет. Все повторные попытки видны в отчёте; повторное исследование учебных случаев не делает их новой независимой выборкой.

## Почему нет цикла optimize

- Только создание/пересборка настройки в `onboard/analyze/collect/reassess` может предложить intent с причиной `onboard` или `context_changed`. `optimize` не выпускает следующий intent.
- Идемпотентность привязана к tenant/company, версии и fingerprint профиля. Новая доставка или новый request ID не обходят её. Обычная новость сама по себе не запускает оптимизацию.
- На стороне Core добавлены cooldown **3600 секунд** и максимум **2 авто-задачи на компанию за UTC-день**. Они действуют независимо от allocation ID. Пропуск — `skipped_frequency`; baseline остаётся рабочим.
- Отдельная конечная allocation ограничивает количество jobs, вызовы, токены, шаги и денежный резерв. Без неё — `skipped_budget`. Неуспешная генерация не получает скрытого платного повтора.

Сквозной Worker-тест доходит до пустой очереди и проверяет отсутствие дополнительных вызовов модели. Проверены быстрые изменения профиля, смена allocation, другая компания и дневной предел. Пропущенный профиль не ставится заново автоматически после cooldown: для повторного запуска нужна явная задача Core. В настоящем Symfony эти проверки нужно подключить к общей транзакции приёма результата.

## Провайдер, расходы и проверка

Все **40 реальных обращений** текущей работы выполнены через **OpenRouter**, `z-ai/glm-5.3-flash`. Расход, включая ошибки: **$0.014119512000**. Накопительно **$0.060988221306 из $5**, остаток **$4.939011778694**; неопределённых списаний и открытых резервов нет. В прежнем экспериментальном пуле использовано $0.008983886 из $0.03 и 24 из 40 вызовов текущего периода. Другие приложения с тем же ключом локальный ledger не учитывает.

Генерация через шлюз Альфы не выполнялась. Ранее отдельно проверены metadata endpoints; неизвестный тариф не равен нулю и не доказывает техническую невозможность генерации. Подтверждение реального шлюза остаётся отдельным подключением.

**439 тестов и 11 subtests прошли** на хосте Python 3.14 и Docker Python 3.12.14. Они проверяют код и границы; содержательные модельные результаты приведены отдельно выше. Есть предупреждение Starlette/httpx, ошибок нет. Схемы API сверены с runtime; JSON-примеры Symfony проверены по моделям и fixture Worker/Core.

Без модели и сети:

```sh
docker compose run --build --rm intelligence demo-research
docker compose run --build --rm intelligence-test
```

Режим baseline получает промежуточные/опровергающие документы и показывает ограничения, но не выдаётся за выполненный модельный причинный разбор. Турнир запускается отдельно через `arena`, с новым run-id при изменении входов/кода. Настоящий Core, интерфейс и шлюз Альфы требуют интеграционной проверки по [инструкции Symfony](symfony-integration.md).
