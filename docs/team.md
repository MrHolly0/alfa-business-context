# Как работать вчетвером

Здесь описано, кто делает следующий кусок работы и что передаёт остальным. Задача команды — собрать один понятный сценарий: одна новость, две компании, две роли пользователя и разные объяснения её значимости.

## Сначала договоритесь о результате

До разработки аналитик бизнеса описывает сценарий и пример ожидаемого ответа. Ответ должен отдельно показывать:

- **Факты** — что прямо подтверждает источник.
- **Позицию банка** — только если есть конкретный банковский материал; иначе написать «неизвестно».
- **Гипотезы** — возможные последствия для компании, которые требуют проверки.
- **Следующий шаг** — что человеку стоит проверить или уточнить.
- **Неизвестное** — каких данных не хватает.

Не подставляйте настоящие данные клиентов. Если пример выдуман или синтетический, подпишите это. Не выводите товарную или причинную связь только из платежей.

## Кто что делает

### Аналитик бизнеса и промптов

Ведёт [сценарий](product/demo-scenario.md): две компании, две пользовательские роли и новость для демонстрации. Для каждого случая пишет, что должно отличаться и почему. Готовит пример ответа с фактами, гипотезами, источниками, неизвестным и следующим шагом. Проверяет, что текст помогает принять решение и не выдаёт догадку за факт.

**Передаёт:** описание сценария, ожидаемые различия и примеры проверки frontend, backend и ML. Сначала согласует поля ответа с ML и frontend.

### Frontend

Работает в `apps/prototype`: собирает веб-сценарий, в котором можно выбрать компанию и роль, открыть новость и прочитать объяснение. Показывает источники, загрузку, ошибку и отсутствие данных. Пока API не подключён, использует согласованный пример данных и явно оставляет его демонстрационным.

**Передаёт:** запускаемый экран, пример данных, способ проверить выбор компании/роли и список полей, которые ждёт от API. Не считает mock данными сервера.

### Backend

Создаёт Symfony/PHP-приложение в `apps/core`: хранение данных и API для создания задачи анализа, проверки её статуса и чтения результата. Сначала уточняет контракт вместе с ML и frontend. Пока Core не готов, не описывает его как работающий сервис и не подменяет им API Node-прототипа.

**Передаёт:** согласованный контракт с примером запроса и ответа, границами ошибок и статусов. Когда появится код — инструкцию запуска и подтверждение, что именно работает.

### ML

Работает в `apps/intelligence`. Сейчас там есть адаптеры разрешённых моделей и локальный учёт расходов. Следующий отдельный шаг — описать и собрать обработку демонстрационной новости: найти подтверждения, сформировать структурированный разбор, сохранить ссылки на источники и честно вернуть неизвестное. Согласует формат результата с аналитиком и API с backend.

**Передаёт:** пример входа и результата, использованные источники, ограничения, учёт вызовов и команду воспроизводимого запуска. Не называет адаптер готовым анализатором новостей.

## Как передавать работу

1. Аналитик фиксирует пример сценария и желаемый результат.
2. Аналитик, ML и frontend согласуют поля результата. Backend и ML отдельно согласуют запрос, ответ и статусы API; frontend подключается к этому формату.
3. Frontend может начать экран на том же примере данных. ML может начать обработку этой же новости. Backend готовит Core API по согласованному контракту.
4. Каждый показывает следующий роли свой результат и получает замечания до подключения. Затем команда проходит сценарий целиком и сверяет объяснение с источниками.

Перед передачей напишите коротко: что готово, как запустить или посмотреть, пример входа и выхода, что осталось и кому нужен следующий результат. Договоритесь, кто редактирует файл; не меняйте один файл одновременно. Если меняется формат данных, сначала сообщите всем его потребителям и обновите пример контракта.

## Ветки и изменения

Начинайте ветку от актуальной основной ветки репозитория и называйте её `feature/<короткая-задача>`, например `feature/analysis-example`. Если основная ветка или порядок слияния неясны, уточните это у команды; не угадывайте имя удалённой ветки. Перед отправкой изменений попросите участника, который использует ваш результат, проверить формат и пример. Коммит называйте так: `docs: описание на русском`, `feat: описание на русском` или `fix: описание на русском`.
