# Статус перенесённого прототипа

Read-only аудит исходного экспорта и перенесённых файлов. В apps/prototype перенесены приложение, tests, fixture, assets и исторические docs; dist, .openai/hosting.json и старые README/START-HERE исключены. Бизнес-логику и UI при переносе не меняли. Этот документ описывает код, а не подтверждает внешние интеграции, безопасность или исходные материалы кейса.

## Что работает

- UI на React 18 и AlfaLab Core Components: каталог ситуаций/событий, фильтры, пагинация, три учебных профиля, локальные действия и история. Состояние в localStorage конкретного браузера (apps/prototype/web/app.js:85–103, :176–180); банковские роли/права не авторизуются.
- Детерминированные правила релевантности/пересмотра, история оснований, поля профиля и сценарные допущения (apps/prototype/web/engine.js:211–407, :415–600).
- Исследования дат в интервале 01.04–22.10.2026, coverage, Pearson и лаги 0/3/7/14 дней считают синтетический ряд, генерируемый формулами (apps/prototype/web/engine.js:612–727). «150 материалов» — генератор вымышленных событий для каталога/пагинации, не архив и не ingest нагрузка (apps/prototype/web/volume-demo.js:24+).
- Экспорт сводки/печать, CSV исследований, ручной текст и контекстные предложения продуктов работают локально; банковский каталог не запрашивается (apps/prototype/web/app.js; apps/prototype/web/bank-products.js:2–45).
- Worker читает две RSS-ленты ЦБ, до 30 публикаций на каждую, объединяет доступные результаты и кэширует минуту в памяти процесса (apps/prototype/worker/index.js:3–14, :195–234, :537–550). Это один издатель, не независимый резерв.
- HTML импорт ограничен allowlist доменов и простым извлечением article/main либо всего тела; метаданные берутся из HTML meta (apps/prototype/worker/index.js:53–71, :236–271). Это не универсальный HTML/PDF парсер.
- Без модели помощник использует правила. С моделью Worker планирует, лексически ранжирует только переданные UI источники, синтезирует, проверяет JSON/ID ссылок и делает максимум один repair (apps/prototype/worker/index.js:273–487). Сервер не подбирает банковский корпус сам; структурная проверка не доказывает истинность.

## API и настройки

GET /api/status, GET /api/news, POST /api/import ({url}), POST /api/analyze ({question, company, sources}); прочие API-пути — 404. POST требует JSON и проверяет Origin, если тот передан; тело максимум 180 KB. In-memory limiter: 4 analyze/min, 20/min прочих путей (apps/prototype/worker/index.js:488–590).

Worker принимает LLM_BASE_URL, LLM_API_KEY, LLM_MODEL, LLM_CASE_MODEL. Код допускает legacy labels, не все совпадают с именами из брифа (apps/prototype/worker/index.js:25–31), и не проверяет соответствие provider ID разрешённой модели (:273–279). Корневой .env.example не содержит ключ. Node сам .env не читает; Compose использует корневой .env, локально env экспортировать или передать через node --env-file.

## Уточнения к README исходного экспорта

- «Резервный источник» — неточно: обе ленты принадлежат ЦБ.
- «Загрузка официальных HTML» — ограниченный парсер с allowlist, без PDF; дата может быть пустой, RSS URL как статья не принимается.
- Утверждение, что инструмент агентного цикла добавляет банковские материалы, расходится с кодом: ранжируется только присланный браузером список, отдельного поиска нет.
- При сбое Worker сохраняет кэш только в памяти; локально сохранённые источники живут в браузере, серверного устойчивого архива нет.
- 150 материалов — synthetic demo, не подтверждение реального ingest или пропускной способности.
- package 10.0.0, но /api/status возвращает версию 6.0 (apps/prototype/worker/index.js:530–536).

Не подключены банковский SSO/ACL, общая БД/серверная история, фоновые jobs при закрытой вкладке, push, отправка менеджеру, общий учёт бюджета LLM, семантический поиск/граф, полный архив новостей и доказательство причинности. Внешняя доступность зависит от сети.

## Запуск и проверка

Исходная сборка зависела от пустого .openai/hosting.json; эта зависимость удалена из build/validate. Build генерирует Worker ESM со встроенными UI/assets; validate проверяет ESM и default.fetch. Root npm run dev сначала строит артефакт. Специальные hosting-пути не нужны.

Из корня:
- npm ci --prefix apps/prototype
- npm test
- npm run build
- npm run validate
- npm run dev
- docker compose up --build --wait

Финальный прогон: `npm ci --prefix apps/prototype` успешно установил 383 пакета; `npm test` прошёл 42/42; `npm run build` и `npm run validate` прошли. Docker build на Node 22.15.0 Alpine установил npm dependencies, собрал Worker ESM с 22 assets и прошёл validate. `docker compose config --quiet` прошёл; контейнер стал healthy и внутри прошли 42/42 теста. HTTP smoke подтвердил главную страницу и четыре прямых UI-ресурса (200), `/api/status` (`mode: rules`, `llm: false`), `/api/analyze` без ключа (400) и host-доступ к `/api/status`. Браузерный E2E, live RSS и реальный LLM-вызов не запускались. Контейнер остановлен после smoke.

Прототип помещён в apps/prototype; root package делегирует команды без workspaces, lockfile сохранён рядом с package. Docker Compose запускает только реально существующий прототип. Будущие apps/core, apps/intelligence, PostgreSQL jobs/очередь добавлять как реализации по контрактам, не как фиктивные сервисы.
