# Сквозная проверка Альфы — 26 октября 2026, обновлено

Три компании прошли через реальный путь Web → Symfony Core → Python → Alfa gateway → сохранение результата Core. Все три вызова анализа вернули HTTP 200; ответы критика приняты строгой проверкой, ошибки отсутствуют. Все три результата имеют статус `partial`; ограничения покрытия и неустановленные зависимости сохранены. Проверка подтверждает интеграционный путь и прохождение валидации ответов, но не качество на независимой выборке или снижение рисков для клиентов.

Для цикла использованы разрешённые материалы хакатона и строго ограниченный Alfa-only маршрут. Выполнено 3×3 модельных вызова. В общем ledger зарегистрированы 13 неопределённых резервирований по 10 ₽ каждое (130 ₽ всего). Валюта локального резерва — RUB; фактическая стоимость вызовов шлюзом не сообщена, поэтому эти резервы не являются подтверждённым расходом или ценой одного запроса. Обычный вызов без точного operator approval для закрытого профиля/материалов остаётся запрещённым; локальный baseline и повторное использование уже разрешённого банковского корпуса не требуют передачи материалов модели.

Финальные проверки: Python **518 passed и 18 subtests**, Core integration tests passed, Web **46 passed**, включая build и artifact validation. Запуск и состав материалов — [инструкция для судей](judging.md). Метрики этой проверки относятся к сохранённым входам и не заменяют независимую экспертизу.

# Синтетическая проверка Alfa — 26 октября 2026

В одноразовом tool image, собранном из текущего исходного кода, выполнен один прямой `LLMService` вызов через `https://changellenge.up.railway.app/v1/chat/completions`. Использована разрешённая модель `google/gemma-4-26b-a4b-it`, короткий синтетический JSON prompt, `max_output_tokens=256`, JSON mode; автоматического повтора не было. Шлюз вернул JSON с `finish_reason=stop`, usage `prompt_tokens=88`, `completion_tokens=14`, `cached_tokens=0`. Это подтверждает реальный транспорт и доступ к Gemma через Alfa, но не полноту рабочего бизнес-сценария, end-to-end путь Core/UI или качество анализа.

Ответ шлюза не содержал фактическую стоимость или валюту: `reported_cost=null`, `cost_currency=null`. Метаданные модели не публикуют input/output ставки. Поле `spend` из `/key/info` не имеет явной валюты, поэтому его значение не принято за RUB и не используется как подтверждение нулевого расхода. Фактическая цена этого вызова неизвестна.

До POST общий PostgreSQL ledger `alfa-hackathon-team` создал ежедневный бюджет 500 ₽ и lifetime cap 500 ₽; до этого у scope ещё не было счёта. После вызова один резерв 10 ₽ остался `uncertain`; дневной `spent=0` означает отсутствие подтверждённой RUB-стоимости, а не бесплатный вызов. Доступный локальный резерв — 490 ₽; счётчик показывает один неопределённый вызов. Та же квота применяется всем ролям и процессам с этим scope/main namespace. Gateway заявляет командный лимит 500 ₽/сутки со сбросом в 03:00 МСК; локальный reserve не является price cap и не доказывает фактическую максимальную цену.

Вызов использовал только синтетический текст и не читал клиентские профили или CSV. Сервис API не пересобирался; проверялся отдельный текущий tool image. Заголовки HTTP-ответа не сохранены в отчёте клиента. Полный judging output cap 4096 настроен отдельно в [`providers.judging.json`](../apps/intelligence/examples/providers.judging.json); этот файл использован в последующей сквозной проверке, описанной выше.

## Настоящие источники и модели

[RSS пресс-релизов ЦБ](https://www.cbr.ru/rss/RssPress) прошёл probe, дал **14 публикаций** за один запрос без ошибок. Сохранены исходные байты и SHA256; HTML внутри описаний нормализуется отдельно, оригинал не переписывается. Другая лента `RssNews` отдала записи без текста: они остались `pending_metadata`, отсутствующий материал не сочинялся. Постоянная подписка и расписание требуют source policy/jobs Core.

Через OpenRouter реально вызывались `google/gemma-4-26b-a4b-it`, `qwen/qwen3.6-35b-a3b` и `z-ai/glm-5.3-flash`. Gemma разбирала общий пакет, Qwen строил персональный ответ, GLM проверял кандидата. Все бизнес-примеры явно синтетические. В положительном контрольном варианте зависимости заданы подтверждёнными **только как условия вымышленного примера**; исходная демонстрационная фикстура по-прежнему хранит их предполагаемыми.

Живые проверки выявили усечение reasoning без текста, смешение банковских и внешних оснований, нехватку входного лимита для repair и слабые переходы от события к бизнесу. Добавлены явные reasoning-настройки, компактная повторная генерация по тем же основаниям, проверка недостающего звена и `partial` при отсутствии найденной связи. В последнем прогоне для перевозчика выполнены анализ/repair/критик, для завода — анализ/критик. Оба вернули цитаты, вопросы и цепочки, оба остались `partial`. Критик также может ошибаться и возвращать невалидные IDs; такие замечания отбрасываются, а запрос review сохраняет ограничение результата.

Формальная готовность и согласие критика не доказывают применимость: в одном предыдущем прогоне критик принял неподтверждённую связь перевозчика с подшипниками. Этот результат не используется как положительный эталон. Корпус пока лексический; глобального web search, learned ranking и проверки на реальных банковских временных рядах нет.

## Как повторить локальную проверку

Из корня:

```sh
docker compose --env-file /dev/null run --build --rm intelligence-test
docker compose --env-file /dev/null run --build --rm intelligence demo-data
```

Из `apps/intelligence`:

```sh
.venv/bin/python -m pytest -q -p no:cacheprovider tests
.venv/bin/python scripts/export_contracts.py --check
.venv/bin/python -m intelligence evaluate --mode baseline --state-dir /tmp/alfa-evaluate
.venv/bin/python -m intelligence arena --state-dir /tmp/alfa-arena run --run-id local-check
```

Модельный повтор запускается отдельно по разрешённому `DataTask`, с явными provider/routes и существующим общим ledger. Pytest и обычный Docker build денег не расходуют. Полные модельные ответы/операционные журналы остаются локальными; [обезличенный машинный отчёт](checks/ai-live-2026-10-24.json) содержит статусы, версии runtime, расходы и ошибки без ключей и текста клиентских данных.

Полную готовность банковского решения и выигрыш качества этот отчёт не заявляет.
