# Демонстрация прототипа и критерии продукта

## Текущий интерактивный прототип

Запустите прототип командами из корневого `README.md`. Откройте локальный адрес, выберите одну из демонстрационных компаний и пройдите основной путь:

1. Просмотрите главную и очередь ситуаций, затем откройте конкретную ситуацию.
2. Проверьте событие, доступные основания и дату/источник; откройте новость и аналитику, если она присутствует в текущей сборке.
3. Сравните, какие признаки компании повлияли на вывод, какие поля остаются неизвестными и что является гипотезой.
4. Перейдите к предлагаемому уточнению, просмотру источника или повторному анализу; покажите, что UI сохраняет состояние/историю согласно реализации текущей версии.
5. Выберите другой профиль компании и сравните очередь и интерпретацию. ID профилей в исходном README названы анонимизированными строками; CSV отсутствует для независимой сверки. Отраслевые ряды/показатели synthetic.

Доступность внешнего RSS и модельного шлюза зависит от окружения. Без ключа шлюза доступен режим правил, который нельзя представлять как фактический вызов LLM. Исходный README сообщает о прочтении первых страниц двух PDF, а не всех девяти аналитических материалов; полный набор PDF/CSV в проекте отсутствует.

## Что проверяется в текущей демонстрации

- Репозиторий установлен, запущен и открывает интерактивное приложение.
- Команда проходит от выбора компании до пояснения события и источников; персональные различия видны на предоставленных/учебных профилях.
- UI различает подтверждённые факты, позицию банка, гипотезы, неизвестное и синтетические данные там, где эти элементы доступны.
- Offline-режим не выдаёт себя за LLM-анализ; сбой источника не превращается в вывод о нулевом риске.

В текущем интерактивном прототипе опциональный API анализа без ключа возвращает ошибку; интерфейс при этом предоставляет режим анализа по правилам. Успешный вызов LLM не подтверждён, пока оператор не настроит и не сверит шлюз.

Проверки текущего checkout завершились успешно: `npm ci` установил 383 пакета; `npm test` прошёл 42/42; `npm run build`, `npm run validate`, Docker build на Node 22.15.0 Alpine и `docker compose config --quiet` прошли. Compose контейнер стал healthy; внутри него прошли 42/42 теста. HTTP smoke: главная страница — 200, четыре прямых UI-ресурса — 200, `/api/status` показывает `mode: rules` и `llm: false`, `POST /api/analyze` без ключа возвращает 400. Проверка host-порта `/api/status` также прошла. Браузерный E2E, live RSS и реальный LLM-вызов не запускались. Подробный read-only аудит текущего состояния — в `docs/web-status.md`. Возможности текущей версии не являются доказательством будущего продуктового acceptance. Новый продуктовый PDF v3 предлагает Symfony/PHP Core + Python AI/Data; это целевая архитектура, а не текущий runtime. Минимальный claim/job слой — техническая часть будущего MVP, а полные production гарантии — пилот.

## Будущее acceptance по кейсу и продуктовому плану

Для оценки решения команда отдельно проверяет сценарий на ранее не показанной новости, релевантность для конкретной крупной компании, влияние на её бизнес, риски/возможности, разумное следующее действие и ссылки на первичные основания. Внутренняя аналитика Альфа-Банка должна быть показана как позиция банка отдельно от выводов модели; отсутствие релевантного материала помечается честно.

Агентная логика должна демонстрировать планирование и шаги с инструментами, общий контекст, самопроверку и ограниченную адаптацию/повтор. Только модели из allowlist брифа; общий дневной предел ключа 500 ₽. Вызовы и usage учитываются, точные API model ID/тарифы не предполагаются без подтверждения. Прототипные fixtures можно применять для демонстрации, но надо подписать, что данные синтетические.

Перед сдачей нужен небольшой независимый holdout: релевантный и нерелевантный материал, риск, возможность, ложная связь, неполные/противоречивые данные и новое событие вне фиксированных правил. Сохранить baseline, rubric оценки доказательности/персонализации, ошибку/пропуски, стоимость/usage и план мониторинга качества с обратной связью экспертов/пользователей. Размер выборки мал; не представлять метрики как промышленную гарантию.
