# Передача проекта

Проект — **Бизнес-контекст**, имя репозитория — `alfa-business-context`, основная ветка — `main`.

## Первый запуск

Нужны Git и Docker с Compose. Получите репозиторий через `git clone` или распакуйте архив исходников, затем из корня выполните:

```sh
docker compose up --build --wait
```

Интерфейс откроется на http://localhost:4173. Для локальной учебной учётной записи используйте `demo@alpha.test` / `DemoAlpha2026!`. Вход, компании, контекст, метрики и новости обращаются к Symfony Core через `/api/`. Кнопка «Посмотреть демо» отдельно открывает старый макет на данных браузера. [Проверка текущего запуска](product-docker-checks.md).

Отдельно проверить весь Python-поток на локальных материалах, без ключей и внешних моделей:

```sh
docker compose run --build --rm intelligence demo-data
```

Пример проходит сбор RSS → документы → события → общий разбор → две компании и выводит JSON-кандидаты. Это синтетические данные, а не банковские выводы.

Проверки:

```sh
docker compose run --build --rm core-test
docker compose run --build --rm web-test
docker compose run --build --rm intelligence-test
```

## Где продолжать работу

| Участок | Файлы | С чего начать |
|---|---|---|
| Интерфейс | `apps/web` | Довести управление источниками и неподключённые рабочие разделы; сохранять отображение ограничений и оснований |
| Бизнес-backend | `apps/core` | Развить существующий Symfony: очередь заданий/lease, автоматическую персонализацию и публикацию; текущий сбор вызывает Python HTTP напрямую |
| Анализ данных | `apps/intelligence` | Python-сбор, поиск, события, модельный анализ, конфигурации и турнир |
| Общая граница | `contracts/intelligence` | Схемы заданий и результатов, OpenAPI и примеры |

Для Backend основная инструкция — [подключение Python](ai-integration.md). [Краткий процесс](ai-process.md) объясняет вход, этапы и выход. [Готовность](ai-scope-and-readiness.md), [проверки](ai-live-checks.md) и [ближайшие задачи](backlog.md) описывают текущий срез. Материалы в `docs/reference` и `apps/web/docs` относятся к исходной версии и ранним решениям; текущую архитектуру смотрите в [architecture.md](architecture.md).

## Настройки и локальные файлы

Для обычного демо ключи не нужны. Для реальных моделей используйте [инструкцию провайдеров](llm-providers.md), собственные ключи и разрешённый бюджет. `.env.example` содержит имена параметров без секретов. Если `.env` уже существует, сохраняйте его; не заменяйте примером.

В Git и архив исходников не входят `.env`, локальные provider configs, IDE-настройки, Python state, зависимости и `.local`. Передавайте исходники через Git или подготовленный архив, а не копированием рабочей папки целиком. Существующие ключи не передаются вместе с проектом.

## Работа с Git

Рабочая версия находится в `main`. Для отдельной задачи используйте короткую ветку, например `feat/company-profile`, `fix/source-filter` или `docs/setup`. После включения изменений в `main` удаляйте завершённую ветку. Коммиты — `type: описание на русском`, без дополнительного соавторства.

Репозиторий: [MrHolly0/alfa-business-context](https://github.com/MrHolly0/alfa-business-context). Получить проект:

```sh
git clone https://github.com/MrHolly0/alfa-business-context.git
cd alfa-business-context
```

Дальнейшие изменения отправляйте в ветку своей задачи. Основная версия находится в `main`. Доступ участникам задаётся в настройках репозитория.
