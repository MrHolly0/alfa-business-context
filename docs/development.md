# Запуск и совместная работа

## Что можно запустить

Сейчас доступны два отдельных локальных запуска: интерфейсный прототип и Python-адаптер. Единого запуска будущих компонентов пока нет. PHP Core находится на стадии плана; команды Composer появятся вместе с первым PHP-приложением.

### React и Node прототип

Из корня репозитория нужны Node.js версии из `.nvmrc`:

```sh
npm ci --prefix apps/prototype
npm test
npm run build
npm run validate
npm run dev
```

`npm run dev` запускает прототип на `http://localhost:4173`. Команда `docker compose up --build` запускает тот же прототип.

### Python-адаптер

Нужен Python 3.12 или новее. Команды выполняются из корня репозитория:

```sh
PYTHONPATH=apps/intelligence python3 -m intelligence.llm
PYTHONPATH=apps/intelligence python3 -m unittest discover -s apps/intelligence/tests -v
```

Первая команда показывает offline-пример без обращения к модели. Настройка профиля описана в [`apps/intelligence/README.md`](../apps/intelligence/README.md). Живой вызов выполняется только отдельной командой `run`; ключ передаётся через переменную окружения. Не помещайте ключи в репозиторий или сообщения команды.

## Работа четырёх направлений

Аналитик уточняет сценарий и ожидаемый ответ. Frontend развивает экран в текущем прототипе. Backend создаёт PHP Core и его API. ML развивает Python-адаптер и следующий шаг анализа. Подробное распределение — в [`docs/team.md`](team.md).

Сейчас можно проверять пользовательский сценарий в прототипе, улучшать адаптер провайдера и согласовывать контракт для Core. Первая задача Backend — создать Symfony-приложение и добавить его команды запуска в `apps/core/README.md`.

Назначайте одного владельца на каждый изменяемый файл. При работе на стыке частей сначала согласуйте пример запроса и ответа. Например, перед изменением данных задания анализа откройте [`contracts/examples/analysis-job.json`](../contracts/examples/analysis-job.json) и описание в [`contracts/README.md`](../contracts/README.md). В примере указаны версия формата, материалы и версии данных; это черновик для обсуждения, а не работающий API. Каждый участник проверяет свою часть по согласованному примеру, без прямых вызовов кода или общей базы другого приложения.

Для отдельной задачи создайте ветку `feature/<короткое-название>`. Коммиты оформляйте как `type: описание на русском`, например `docs: упростить запуск Python`.

Перед передачей результата напишите, что готово, как это запустить или посмотреть, какие примеры использованы и что осталось. Выполните команды проверки для затронутой части выше и укажите результат. Если проверяли только прототип или Python-адаптер, так и назовите проверенную часть.
