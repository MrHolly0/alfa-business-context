# Турнир настроек

Обычный анализ берёт готовую конфигурацию. Турнир запускается отдельно: он сравнивает `baseline@1` и до трёх вариантов на одинаковых новостях и профилях компаний. Настройки могут менять фокус, горизонт, стиль и порядок поиска. Системные правила, доступ к источникам и проверки ответа остаются общими.

## Проверить без ключа

Из корня проекта:

```sh
docker compose run --build --rm intelligence arena list
docker compose run --rm intelligence arena generate
docker compose run --rm intelligence arena run --run-id demo-1
docker compose run --rm intelligence arena review-pack --run-id demo-1
```

Учебный набор `evaluation/tournament-demo.json` содержит три тренировочных и два отложенных случая. В режиме `baseline` модель не вызывается, судья возвращает ничью. Это проверка механики; учебный победитель не допускается к публикации.

## Что происходит в прогоне

1. Фиксируются входные запросы, документы, версии настроек, промпта, кода и провайдера. Компании и события из отложенной части не должны встречаться в тренировочной.
2. Все участники проходят тренировочные случаи. Код проверяет формат, ссылки, хеши цитат, доступ к источникам, даты, лимиты и ожидаемые условия сценария. Сбой исключает ответ из победы; проверка ссылок сама по себе не доказывает истинность вывода.
3. Судья сравнивает каждого конкурента с базовым вариантом в обоих порядках. Он получает компанию, событие, источники и ответы без названий конфигураций. Расхождение при перестановке — ничья. При равном выигрыше нескольких вариантов остаётся базовый.
4. Только предварительный победитель и базовый вариант проходят отложенные случаи. Ошибка или ухудшение в сравнении оставляет базовый вариант. Сбой судьи не считается успешной проверкой.
5. Человек получает отдельный слепой пакет с контекстом и источниками. Ручная оценка и успешная отложенная проверка нужны для публикации. Автоматический отчёт не заявляет измеренное качество продукта.

`--critic` в модельном режиме добавляет один разбор спорных утверждений на тренировочном случае перед отложенной проверкой. Ссылки критика проверяются. Автоматического переписывания конфигурации или нового поиска по замечаниям пока нет; замечания сохраняются для следующей версии.

## Вызвать модель

Выберите разрешённый платный конфиг в `.env`, как описано в [инструкции провайдера](../../../docs/llm-providers.md). Явный запуск:

```sh
docker compose run --rm intelligence arena generate --mode model --config /config/providers.json --profile openrouter
docker compose run --rm intelligence arena run --run-id model-1 --mode model --config /config/providers.json --profile openrouter --candidates baseline@1,finance@1
docker compose run --rm intelligence arena budget --config /config/providers.json --profile openrouter
```

`generate` регистрирует принятые варианты и печатает их ref. Передайте нужные ref через `--candidates`. По умолчанию `run` сравнивает четыре встроенные версии. Все роли расходуют один общий бюджет и отдельный экспериментальный пул: для платных тестов OpenRouter по умолчанию $0.03 в сутки, максимум 40 вызовов за период. `--experiment-limit` не может превышать 20% общего лимита. Генератор, анализ, исправления ответа, судья и критик учитываются в этих лимитах.

Для другого судьи передайте `--judge-config` и `--judge-profile`; конфиг должен использовать ту же валюту, общий `budget_scope` и дневной лимит. Для генерации выберите конфиг Qwen командой `generate`, для судьи — GLM, если их доступ и тарифы подтверждены. Без отдельного конфига используется выбранная модель разработки. Автоматической смены модели нет.

Завершённые ответы и сравнения сохраняются в SQLite и используются повторно для тех же входов. При прерывании резерв остаётся закрытым для автоматического повтора. Повторный `run-id` с другими входами отклоняется. `--shadow` означает прогон без права публикации; это не подключённая проверка на производственном трафике.

## Оценить, опубликовать, откатить

Для работы на хосте из `apps/intelligence`:

```sh
python -m intelligence arena review-pack --run-id model-1 --output /tmp/blind-pack.json
python -m intelligence arena review --run-id model-1 --reviewer team --ratings /tmp/ratings.json
python -m intelligence arena promote --run-id model-1 --scope 'impact:finance:*' --reviewer team --expected-revision 0
python -m intelligence arena active --role 'Финансовый директор' --industry 'логистика'
python -m intelligence arena rollback --scope 'impact:finance:*' --reviewer team --expected-revision 1
```

В `ratings.json` нужен объект с каждым `blind_id` из пакета и выбором `A`, `B` или `tie`. Для слепой оценки передавайте человеку только `review-pack`, а полный `show` смотрите после оценки. В Docker используйте тот же volume и примонтируйте файл оценок read-only. Хост и Docker по умолчанию имеют разные каталоги состояния; не смешивайте их отчёты.

Публикация разрешена только для несинтетического модельного прогона, выигравшего сравнение и прошедшего отложенную и ручную проверки. `expected-revision` — текущая ревизия активации области, первая равна 0. Откат добавляет запись в историю и возвращает предыдущую версию. Новая компания сразу получает опубликованные настройки своей роли/отрасли или базовый вариант, без отдельного турнира.

Настройки для ручной правки можно выгрузить командой `arena export --ref finance@1 --output /tmp/analyst.json`. Измените ID или увеличьте `revision`, затем выполните `arena register --input /tmp/analyst.json`. Существующая версия неизменяема. [Формат настроек](analysts.md).
