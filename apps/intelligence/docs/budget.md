# Лимиты живых проверок

`examples/providers.live.template.json` задаёт отдельно разрешённый режим: OpenRouter — до $5 суммарно, до $5 в сутки, до $0.25 резерва на вызов; шлюз Альфы — до 500 ₽ суммарно и в сутки. Суммарный лимит не обновляется при смене даты. Это потолок расходов, а не цель потратить всю сумму. [Измеренные расходы](../../../docs/ai-live-checks.md).

Исходный платный шаблон сохраняет $0.20 в сутки и $0.01 на вызов. Для повышения нужен явный `lifetime_limit` не более $5. Тарифы `null` не означают бесплатный вызов: профиль Альфы заблокирован до подтверждения ставок в RUB, включая reasoning и другие тарифицируемые категории.

Все роли, repair, генератор, судья и турнир используют тот же SQLite ledger и account scope. Не создавайте новый scope или ledger, чтобы начать расход заново. Лимит локален: вызовы того же ключа из других приложений надо сверять отдельно с провайдером.

Если оператор уже разрешил повышение существующего лимита, изменение делается через compare-and-set с сохранением всех расходов:

```sh
docker compose run --rm intelligence llm configure-budget \
  --scope alfa-openrouter-paid-tests --currency USD \
  --daily-limit 5 --lifetime-limit 5 \
  --expect-daily-limit 0.20 --expect-no-lifetime-limit --confirm
```

Команда не редактирует ключи и конфигурацию. При несовпадении прежних значений она отказывает. Не повторяйте этот пример после того, как лимит уже изменён. Для каждого вызова по-прежнему нужны известные тарифы, допустимая цена, разрешённые данные и резерв до отправки. Неопределённое списание удерживает резерв; скрытого повтора нет.
