# API и задания Core

Python запускается двумя командами: `serve` принимает внутренние HTTP-запросы, `worker` получает задания от PHP. Оба используют один конвейер анализа. CLI хранит данные в `.state`; Docker — в томе `/app/.state`.

`/health` проверяет процесс. Импорт, поиск, ранжирование и анализ требуют сервисный токен и разрешённый tenant. Пустой токен или список tenant закрывает доступ. Пользовательские сессии проверяет PHP; Python получает от него уже разрешённый профиль и источники.

Повтор анализа с тем же tenant/request ID возвращает сохранённый результат. Другое тело под этим ID даёт конфликт. Одновременный повтор не запускает модель второй раз. Если процесс оборвался в неопределённый момент, автоматического перезапуска нет: сначала нужно проверить состояние и возможный расход.

Перед запуском API создаёт durable reservation с уникальным owner token. Если `DataWorkflow` подтверждает типизированной ошибкой `WorkflowNotStarted`, что обработка не начиналась из-за занятой ёмкости, API атомарно снимает reservation только при совпадении tenant, request ID, hash тела и owner token; этот же запрос можно безопасно повторить после освобождения ёмкости. Любой обычный сбой, тайм-аут или неопределённый исход сохраняет reservation и блокирует автоматический повтор. Старый владелец не может снять или завершить reservation нового владельца; восстановление неопределённого запуска остаётся явной операцией оператора.

Worker проверяет компанию, версии контекста, события и политики источников, лимиты и срок задания. Пока модель отвечает, отдельный поток продлевает lease. После отмены, истечения срока или потери lease новые шаги не выполняются, результат не отправляется. Уже отправленный запрос модели может завершиться и тарифицироваться — его расход сохраняется.

Кандидат и исходящее сообщение записываются в SQLite одной транзакцией. Если подтверждение потерялось, повторяется то же сообщение с прежними payload и ID; модель заново не вызывается. SQLite непосредственно перед каждым сетевым вызовом атомарно резервирует одну отправку с отдельным токеном и сроком блокировки; параллельные процессы не отправляют одну запись одновременно, а опоздавший процесс не может изменить попытку нового владельца. Worker пытается доставить до 10 готовых сообщений за запуск, затем может получить новое задание, даже если отдельная доставка временно недоступна.

Для временных ошибок сохраняются число попыток, время следующей попытки, ограниченный срок хранения (24 часа) и последняя причина. Интервал растёт экспоненциально с небольшим случайным разбросом и ограничен сверху. После восьми попыток или срока хранения запись попадает в `outbox_dead`; явный конфликт, устаревший lease и отказ доступа также сразу отправляются туда. Успех засчитывается только при ACK с совпадающим ID. Команда `python -m intelligence inspect` показывает ожидающие отправки и `outbox_dead`. Программный просмотр доступен через `ArtifactStore.pending()` (включая attempts/next_attempt_at/retry_deadline/claim_until/last_error) и `ArtifactStore.dead_letters()`.

Адрес Core задаёт оператор через `CORE_BASE_URL`, токен — через `CORE_SERVICE_TOKEN`. Редиректы запрещены, ответ ограничен 4 МБ. API принимает до 2 млн символов текста либо PDF до 20 МБ в base64; весь JSON ограничен 30 МБ.

[Точные маршруты, схемы и ACK](../../../contracts/intelligence/README.md). [Docker и восстановление после сбоя](../../../infra/README.md). Настоящий PHP ещё не подключён; обмен проверяется с подставным Core.

Платный OpenRouter разрешается только отдельным конфигом с `allow_paid`, ограничениями цены/расхода и USD-резервом внутри задания. Общий локальный журнал хранит доллары отдельно от рублей хакатонного шлюза.

Новые поля retry добавляются к существующей SQLite без удаления сообщений и изменения их payload. Одновременный запуск миграции сериализуется. Срок блокировки отправки — 60 секунд; HTTP-клиент Core ограничивает сетевой вызов 30 секундами. При паузе процесса дольше блокировки запрос может быть повторён; уникальный ID и дедупликация на стороне Core остаются обязательными. Токен защищает локальную запись от изменений опоздавшим процессом.
