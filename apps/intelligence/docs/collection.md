# Сбор и проверка источников

`intelligence.collection.NewsCollector` выполняет сбор по неизменяемому `SourcePolicySnapshot`, переданному Core для конкретной работы. Он не создаёт источники, не хранит пользовательские настройки, не решает права и не меняет их. Core остаётся владельцем effective policy revision, включая общие/пользовательские исключения по источнику, издателю и canonical URI. Python применяет исключение известного HTML/PDF URL до сетевого запроса, а исключение каждого элемента feed/API — до записи normalized document. Для прямой HTML-страницы исключённого издателя, которого нельзя узнать до загрузки её metadata, байты не сохраняются и документ не попадает в corpus; исключённая feed/API запись отбрасывается.

Экспортируемые контракты: `SourcePolicySnapshot`, `SourceGrant`, `JSONAdapterMapping`, `SourceProbeRequest`, `SourceProbeResult`, `CollectionDocument`. Снимок предоставляет `effective_sources()`, `effective_source_ids()`, `permits_document(metadata)` и `is_personally_hidden(metadata)`. Общие исключения источника/издателя/материала применяются к сбору и аналитике; личное скрытие источника, издателя или URL применяется только к персональной видимости и не меняет источники компании, сбор или аналитический доступ к уже сохранённому документу. Право исключить материал из анализа задаётся отдельной общей политикой и версией Core. `NewsCollector.collect(snapshot, *, now=None, source_ids=None, force=False, checkpoint=None)` возвращает обычный JSON-совместимый `dict`; его `documents` массив содержит `tenant_id`, `source_id`, роль, canonical URL, нормализованный текст, тип документа, даты публикации/события/получения, издателя, автора, язык, корпусный `document_revision_ref`, content hash и SHA256/`raw_ref` исходного ответа. `source_ids` может только сузить снимок; попытка передать ID вне effective policy отклоняется. Если передан callback `checkpoint(stage)`, он вызывается перед/после источника, до/после каждого HTTP-запроса и при обходе feed/API записей; его исключение пробрасывается вызывающему коду без преобразования в ошибку источника.

`NewsCollector.probe(SourceProbeRequest)` проверяет разовую ссылку по одноразовому grant Core. Grant содержит точный URL, tenant, срок, список разрешённых hosts и типов. Probe возвращает `ready`, `needs_metadata`, `unsupported` либо `error`, найденные поля, preview, raw SHA256 и список неизвестных полей. Для ленты `ready` означает, что источник распознан и найден publisher на уровне ленты; это не обещание, что каждая запись содержит текст статьи. Если запись RSS имеет заголовок/дату, но пустой description, она остаётся `pending_metadata` с `missing_fields=["content"]`. Для таких лент нужен grant с `fetch_articles=true` и явным `article_hosts` либо другой разрешённый формат/endpoint с содержанием. В проверке CBR `RssNews` часть записей не имела текста; это ожидаемый результат источника, а не ошибка парсера. Probe не создаёт подписку или запись источника. Дата публикации никогда не подменяется временем загрузки: материал без даты попадает в `pending_metadata` и не становится документом корпуса.

Поддерживаемые типы: RSS/Atom, HTML, PDF и JSON API с декларативным mapping-адаптером. JSON mapping задаёт только ограниченные dot-path поля, не код, произвольные URL или заголовки; обязательны массив элементов, title, content, URL и дата публикации. Новые API-схемы требуют отдельного проверенного mapping. RSS/Atom ограничены 100 записями за источник/запуск; JSON также ограничен 100 элементами. До десяти страниц из RSS можно получить только при `fetch_articles=true` и заданном `article_hosts`.

Каждый HTTP(S) запрос ограничен 20 секундами и 2 МБ. HTTPS обязателен; запрещены credentials в URL, чувствительные query-параметры, нестандартный порт, непубличные IP и DNS-ответы со смешанными публичными/непубличными адресами. DNS разрешается до соединения, TLS проверяет сертификат исходного hostname, а сокет соединяется с выбранным IP. Перенаправления ограничены двумя шагами; каждый новый hostname должен входить в список Core grant и заново проходит ту же DNS/TLS-проверку. Используется прямой сокет без системных proxy-переменных, cookies и произвольных HTTP-заголовков; разрешены только ограниченные validators ETag/Last-Modified. Автоматического обхода ссылок нет.

Точные полученные байты сохраняются content-addressed по SHA256 в `raw_dir`; если он не задан, используется каталог `raw` рядом с `state_path`. Файлы лежат под SHA256-хешем tenant ID, права каталогов/файлов ограничены на POSIX, а в отчёте `raw_ref` указывает на blob и `raw_sha256` подтверждает совпадение с байтами. Операционная SQLite также сохраняет `raw_receipts` с точным URL, автором/издателем/датами, хешем оригинала и corpus revision ref. `author`, `event_time`, `raw_sha256` и `raw_ref` передаются в `CorpusStore.ingest`; CorpusStore хранит доступные ему поля provenance. Для исходного ответа коллектора авторитетными остаются его точные bytes receipt и `raw_ref`; извлечённый текст не выдаётся за исходный feed/API payload.

Для RSS/Atom эти оригинальные байты сохраняются без изменений. Текст описания записи, который идёт в корпус и цитату, нормализуется отдельно: CDATA/escaped HTML очищается от тегов, скриптов, стилей и HTML-сущностей. Поэтому цитата может отличаться от исходной разметки; для сверки используется receipt с `raw_ref` и `raw_sha256`.

SQLite в `state_path` хранит operational poll state: ETag, Last-Modified, next poll, попытки, статус, код последней ошибки и fingerprint source grant. Fingerprint вычисляется из immutable grant, включая URI, parser/content type, mapping, allowlist, classification и лимиты, но не из policy revision. Изменение grant сбрасывает due/validators и разрешает запросить новую конфигурацию сразу; старый медленный запрос не перезапишет состояние нового grant. Additive migration `lease_until`/`grant_fingerprint`/`lease_generation`/`lease_token` выполняется под `BEGIN IMMEDIATE`. Каждая lease получает случайный claim token и возрастающее поколение; запись результата, ошибки или освобождение допускаются только владельцу совпадающих token, generation и grant fingerprint. Поэтому завершившийся поздно запрос не меняет расписание, validators, attempts или lease нового владельца. Параллельные процессы не опрашивают одну `(tenant_id, source_id)` одновременно; lease освобождается после завершения или истекает после падения. Обычный запуск соблюдает `poll_interval_seconds`; `force=True` обходит только срок следующего poll, но не policy, блокировку активного запроса и сетевые ограничения. Это не планировщик и не второй job lifecycle. Core scheduler/worker вызывает `collect` без открытого браузера и передаёт checkpoint для быстрой остановки при потере lease. После сбоя применяется backoff с jitter; `Retry-After` понимает секунды и HTTP-date и не сокращает запрошенную сервером задержку. Если seconds выходит за представимый диапазон datetime, next poll ставится на `datetime.max` UTC (фактически приостановка до изменения grant/операторского вмешательства).

Изменение grant classification не повышает задним числом уже сохраненную закрытую ревизию до `public`. Классификация остаётся на каждой нормализованной ревизии; report показывает фактическую сохранённую классификацию CorpusStore, а исходные bytes остаются отдельным immutable receipt. Поэтому при смене `confidential` → `public` новые версии оригинала могут быть получены, но ранее confidential материал останется confidential и не станет доступен внешней модели.

`examples/sources.template.json` показывает форму snapshot, а не список уже разрешённых изданий. Core обязан заменить placeholder-ы и выдать актуальную policy revision. Доступ, лицензии и право сохранять оригиналы подтверждает владелец данных; запись permission или разрешённого source в шаблон не создаёт такого разрешения.
