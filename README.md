# Бизнес-контекст

Сервис новостной аналитики для руководителей крупного бизнеса. Он связывает событие с контекстом компании: объясняет возможное влияние, показывает источники и помогает определить, что проверить дальше.

Контекст компании может содержать несколько направлений, ресурсы и зависимости с происхождением и актуальностью. Настройки аналитика версионируются и применяются в рабочем анализе.

Результат разделяет внешний факт, позицию банка, гипотезу и неизвестные данные. Если для вывода нужны сведения о договоре, запасах или поставщике, сервис формирует уточняющий вопрос.

## Что есть в репозитории

| Компонент | Каталог | Текущее состояние |
|---|---|---|
| Интерфейс | `apps/web` | React и компоненты Альфы; выбор компании, лента и разбор событий на демонстрационных данных |
| Анализ данных | `apps/intelligence` | Python: сбор источников, документы и события, общий разбор, персональный анализ, пересмотр, конфигурации и турнир |
| Бизнес-ядро | `apps/core` | Контур Symfony/PHP для прав, профилей, источников и публикации; пока описан контракт, реализации PHP нет |

Python-модуль проверяется отдельно через CLI, внутренний HTTP API и контрактный стенд Core. Связь интерфейса с настоящим PHP API ещё предстоит подключить.

## Быстрый запуск

Нужен Docker с Compose. Из корня репозитория:

```sh
docker compose up --build --wait
```

Интерфейс: **http://localhost:4173**. Для демонстрации ключи не нужны. Пока PHP не подключён, `/api/` отвечает `503`, а интерфейс использует локальные данные.

Отдельно запустите сквозной пример анализа без внешней сети и моделей:

```sh
docker compose run --build --rm intelligence demo-data
```

Пример читает локальную RSS-ленту и учебную аналитическую заметку, сохраняет документы, объединяет публикации в события и готовит результаты для двух вымышленных компаний. В терминале появится JSON: **два события и четыре кандидата анализа**, со ссылками на основания, вопросами и ограничениями. Режим `baseline` проверяет работу потока; он не строит полноценную модельную интерпретацию.

Остановка: `docker compose down`. Сохранённые данные Python остаются в Docker volume.

## Как проходит анализ

1. Core передаёт контекст компании, разрешённые источники и версии настроек.
2. Python получает материалы, сохраняет оригиналы и версии, объединяет перепечатки.
3. Общий разбор события используется для нескольких компаний. Известные зависимости помогают найти возможное влияние.
4. Исследователь, аналитик и критик выполняют ограниченные этапы поиска и проверки. Код контролирует источники, ссылки, число вызовов и расходы.
5. Результат содержит объяснение, основания, допущения, альтернативы и следующий вопрос. При изменении контекста или источников анализ пересчитывается.
6. Core проверяет актуальность кандидата и решает, публиковать ли его пользователю.

Сбор новостей входит в Python-модуль. Пользовательские настройки источников, права и расписание принадлежат Core. Подробности: [процесс](docs/ai-process.md) и [подключение Backend](docs/ai-integration.md).

## Проверки и ограничения

```sh
docker compose run --build --rm web-test
docker compose run --build --rm intelligence-test
```

25 октября 2026 на хосте и в Docker прошли **439 тестов Python и 11 subtests**. Последняя проверка интерфейса 24 октября — **37 тестов**. Отдельно проверены реальный RSS ЦБ и вызовы Gemma, Qwen и GLM через OpenRouter. Регрессии и исправления — в [отчёте ревью](docs/ai-review-and-fixes.md); живые прогоны и расходы — в [отчёте моделей](docs/ai-live-checks.md).

Новый смешанный сценарий: `docker compose run --build --rm intelligence demo-business`; он использует локальные RSS. Сравнение персональных сигналов для двух компаний одной отрасли и смешанного бизнеса: `docker compose run --build --rm intelligence demo-personalization`; JSON содержит одинаковые события, поисковые запросы и результаты. Сигнал — эвристический приоритет, не вероятность. Подробности и ограничения: [персонализация](docs/personalization.md), [отчёт сравнения](docs/checks/personalization-comparison-2026-10-25.json). Итоговые [проверки и расходы](docs/research-and-tournament-checks.md) включают реальные Qwen, Gemma и GLM.

Смысловое качество и выигрыш от турнира пока не подтверждены независимой разметкой. Реальные банковские CSV/PDF не включены в репозиторий. Генерация через шлюз Альфы ожидает подтверждения тарифов; настроенные адаптеры не означают проверенную генерацию через этот шлюз. Источники, ограничения и статус каждого требования описаны в [матрице готовности](docs/ai-scope-and-readiness.md).

Косвенные цепочки, опровержение и исследование неизвестной зависимости: `docker compose run --build --rm intelligence demo-research`. [Результаты настоящей модели и турнира](docs/research-and-tournament-checks.md), [точное подключение Symfony](docs/symfony-integration.md).
