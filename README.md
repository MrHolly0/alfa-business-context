# Новостная аналитика для бизнеса

Команда делает прототип, который помогает руководителю понять, какие новости важны для его компании и почему. Хороший результат показывает источники, отделяет известные факты от предположений и подсказывает, что проверить дальше.

Для начала прочитайте [ближайшие задачи](docs/backlog.md) и [как работать вчетвером](docs/team.md). [Схема проекта](docs/architecture.md) объясняет связь PHP, Python и интерфейса; [инструкция разработчика](docs/development.md) содержит команды.

## Что сейчас в репозитории

- `apps/prototype` — работающий самостоятельный интерфейс React и сервер Node с демонстрационными правилами. Это текущий прототип.
- `apps/intelligence` — отдельный Python-инструмент для вызова разрешённых моделей через шлюз и записи расходов в локальную SQLite-базу. Это ещё не обработка новостей и не полный сервис анализа.
- `apps/core` — место для будущего Symfony/PHP Core. Сам сервис пока не реализован.
- `contracts` — описания и примеры будущих API-контрактов. Наличие контракта не означает, что endpoint уже работает.
- `docs` — требования, состояние прототипа и подробные материалы по проекту.

Прототип и Python-инструмент пока работают отдельно. Следующая задача — соединить интерфейс, PHP-ядро и Python-анализ.

## Запустить интерфейс-прототип

Нужен Node.js 22.15.x. Из корня проекта:

```sh
npm ci --prefix apps/prototype
npm run dev
```

Откройте адрес, который напечатает команда (обычно `http://localhost:4173`). Остановка — `Ctrl+C`. Команда `npm run dev` собирает прототип и запускает локальный просмотр. `npm test`, `npm run build` и `npm run validate` относятся только к `apps/prototype`.

## Запустить Python-инструмент

Нужен Python 3.12 или новее. Команда запуска offline-режима из корня:

```sh
PYTHONPATH=apps/intelligence python3 -m intelligence.llm
```

Она проверяет CLI без обращения к модели. Настройка и отдельный явный live-вызов описаны в [инструкции по адаптерам](docs/llm-providers.md). Для live-вызова нужен выданный ключ и согласованный профиль; не кладите ключ в Git. Этот инструмент пока не подключён к интерфейсу-прототипу.

## Четыре участника и первый общий результат

| Кто | Своя часть |
|---|---|
| БА + промпты | Сценарий в `docs/product`, ожидаемые ответы и проверка качества |
| Frontend | Экран и взаимодействие с пользователем в `apps/prototype/web` |
| Backend | PHP-ядро, хранение данных и API в `apps/core` |
| ML | Поиск, разбор новости и вызовы моделей в `apps/intelligence` |

Конкретные задачи и передача результатов — в [памятке команды](docs/team.md).

Первый общий сценарий: показать одну новость для двух компаний и двух ролей пользователей. Для каждой пары объяснить значимость, привести подтверждающие факты и источники, отдельно пометить гипотезы и неизвестное. Если данных недостаточно — так и сказать. Пока это цель разработки, а не готовая функция.

## Правила, полезные всем

- Перед началом задачи договоритесь, какой результат можно показать и как понять, что он готов.
- Для параллельной работы сначала согласуйте формат данных. На один файл в каждый момент назначайте одного автора.
- Перед передачей следующему участнику приложите пример входа и выхода, что уже работает и что ещё не готово.
- Не придумывайте связь компании с новостью по одному совпадению или платежу. Показывайте источник каждого факта.
- Подробная очередь задач находится в [плане](docs/backlog.md); технические детали — в документах рядом с кодом.
